## 真实入口

```sh
python3 scripts/studio.py intent '给这条现有视频做标题、封面、标签和离线发布包，先不发布'
python3 scripts/studio.py content-plan productions/operations-integration-20261114/message/context.json
python3 scripts/studio.py plan productions/operations-integration-20261114/message/production-brief.json
python3 scripts/studio.py publish-verify works/read-message-1114/publications/v0001/douyin/p0001
python3 scripts/studio.py --mode delivery workflow productions/operations-integration-20261114/message/analytics-task.json
python3 scripts/studio.py content-analyze works/read-message-1114/publications/v0001/douyin/p0001 --feedback productions/operations-integration-20261114/message/feedback.json
python3 scripts/studio.py content-plan works/read-message-1114/analytics/v0001/douyin/p0001/a0001/next-brief.json
```

`publish-check`、`publish-verify`、`content-analyze` 只读。`publish-pack`、`content-review` 必须显式 `--mode delivery`，同作品使用既有 `.lock`；模式不是对外授权。`workflow` 只核交接，不执行后续命令。复盘交接示例见同试点目录 `analytics-task.json`。

新包沿`publish-check <新spec>` → `--mode delivery workflow <publish交接单>` → `--mode delivery publish-pack <同一新spec>`；三处共用检查，缺项先拒绝。两份旧spec缺本次新增合同，现只作历史实跑参考，不能直接重建；不要补造旧出图的模型和生成前研究。既有包仍可直接`publish-verify`和复盘。

首次构建用 `python3 scripts/studio.py --mode delivery publish-pack <spec.json>`；两条演示p0001已存在，再构建会拒绝覆盖。调整封面或文案后填写新p修订再构建。保存一次新复盘用 `python3 scripts/studio.py --mode delivery content-review <包目录> --feedback <反馈.json>`，每次新增a修订，不需要为查看已有报告重复保存。

## 受众与选题先进入制作

`content/accounts/`保存账号方向、受众处境、栏目、语气和禁用承诺；`content/topics/`保存观众问题、观看回报、内容角度、开头、视觉计划、内容承诺和带限制的证据。context用文件与SHA绑定两者，`content-plan`输出冻结的`content_strategy`和`creative_contract`。

制作brief声明`purpose: self-media`并携带同一`content_strategy`，原`plan`展示实际内容合同，原`validate/make/resume`拒绝缺策略或未就绪选题。模板选择、原生工程和已有编辑/恢复合同保留；不能把所有模板演示都当作某账号的内容。现片包装从实际视频反查选题，不为配标题虚构教学效果。[阶段共用方法](../.agents/skills/self-media-studio/references/受众到复盘.md)说明Skill与CLI交接。

## 包装合同

历史输入：[剧情实跑 spec](../productions/operations-integration-20261114/message/spec.json)、[日程实跑 spec](../productions/operations-integration-20261114/calendar/spec.json)。由Codex阅读同版内容后填写，而非脚本从request猜公开文案。新增包固定写schema 3，必须满足下列全部字段；schema 1/2旧包仍可核验，输入自报旧schema不会降低新建要求。

| 字段 | 合同 |
|---|---|
| source | `project`、`version`、`video_sha256`、`receipt_sha256`，来自 `publishing.source(studio, id, version)`；实际制作入口 `check_delivery` 再核原交付 |
| strategy | `{file, sha256}`引用context；账号、选题文件哈希与内部冻结快照均核对；须为ready且账号/平台一致 |
| platform / account_alias / revision | 当前仅 `douyin`；账号别名为定位标识、不含认证；包装修订 `p0001` 起，存在则拒绝覆盖 |
| titles / selected_title | 恰好3个 `{text, reason, promise_id}` 与选中序号0–2；先展开角度再收敛，Codex核内容依据与自然表达 |
| covers / selected_cover | 恰好2个 `{file, sha256, angle, promise_id}` 与序号0–1；不同视觉概念，`file`相对spec，输入PNG，包内统一命名 |
| description / tags | 面向公众重新写的正文；标签为独立、相关、不重复的词，不含井号与空格；无固定“最佳数量”结论 |
| editorial | `fulfillment`逐条绑定承诺、片内秒数与观察；`tag_basis`逐标签说明role/basis/evidence_id；两条`cover_observations`对应实际图片审查 |
| cover_research | `selection_reason`及非空`references`；逐条含唯一`id`、HTTPS原帖`url`、`checked_at`、`metrics:{views,likes}`（未知null）、`metrics_source`、`visual_observation`、`relevance`、`limitation`。实际看到封面才作为生成参考 |
| covers[].generation | `tool=image_gen.imagegen`、`requested_model=Codex Image 2`、`reported_model`（工具未暴露填null）、`prompt`、`evidence`、`image_sha256`、`reference_ids`；图片哈希与本张一致，引用本次研究。SVG可草图，不作最终来源，不静默换模型 |
| review | `video_sha256`、`content_observation`、`limitations`和下述`checks`；只代表实际审查范围，不是机器审美评分 |
| rules | `source`、`checked_at`；本阶段不接平台能力接口，不保证实时字段限制 |
| experiment | `hypothesis`、`variable`；未来单变量观察依据，当前无因果结论 |

`review.checks`恰好覆盖`video_visual`、`video_audio`、`cover_visual`、`platform_crop`、`user_acceptance`五层。每条写`layer/status/scope/method`，状态为`observed/issue/unobserved`；前两种必须有`evidence`。抽帧不等于全片、图片观察不等于平台裁切、有限用户意见不等于整片认可。未看/未听保持unobserved，有问题如实issue；无需伪造通过才能交付候选。

新包/预览/复盘显示独立`quality`：始终为candidate，列pending、issues与model_verification。`not_exposed`表示底层模型未知，`reported`也只代表记录中有模型名。`offline_ready`仅指文件包就绪。程序核结构和产物绑定，不认证工具调用、原帖指标真假、审美或人审；`publish-verify`会重新计算质量摘要，不能只改摘要并重写回执凑通过。获准新制作时，必须用实际新出图证据跑完整schema 3包；旧图不补造新模型来源。后续p0002实例以上方“实际新包”为准。

输出在 `works/<id>/publications/<version>/douyin/<p版本>/`，包括同字节视频、两个封面、候选与最终文案、预览、含策略快照和编辑依据的manifest及本地回执；同级ZIP可解压移交。非空字幕才复制，空SRT不伪装成可用字幕。制作原生包、开发brief、源码、原始request和凭据不复制进包。预览页面无外部依赖、上传控件或账号连接，携带内容安全策略。当前发布包含内部编辑依据，属于交接资料；实际公开文案只有final对应内容。

原制作目录和 `current.json` 保持不动。构建前后核来源；包内文件由独立回执绑定。改文案/封面生成新p版本，不渲染视频；原片/原回执哈希变化时旧包核验拒绝。ZIP中的包可用 `publish-verify <解压目录>` 对照本机原制作源核验；没有原项目的电脑可以预览媒体，但不能声称已复核原制作源。

## 真实指标合同

```json
{
  "platform": "douyin",
  "account_alias": "实际账号别名",
  "content_id": "平台真实作品ID",
  "source": "后台导出文件或截图的可追溯说明",
  "video_sha256": "与发布包一致",
  "publication_manifest_sha256": "与发布包manifest一致",
  "published_at": "2026-11-14T10:00:00+08:00",
  "observed_at": "2026-11-15T10:00:00+08:00",
  "window_hours": 24,
  "content_type": "knowledge-animation",
  "duration_seconds": 30,
  "metrics": {"impressions": null, "views": null, "likes": null, "comments": null, "shares": null, "saves": null, "followers": null},
  "missing_reasons": {"impressions": "该后台未提供曝光字段"}
}
```

以上是**字段模板，不是真实发布记录**；全空模板会拒绝导入。源文件SHA、原快照与发布包SHA写入复盘记录。提供真实数据后运行 `content-analyze <包> --metrics <JSON> [--baseline <其他作品JSON>]`；保存时改用 `--mode delivery content-review`。标注 `synthetic=true` 的演示数据会拒绝导入。程序检查结构、绑定与时间，不能替代对后台来源真实性的核对。

只比较同平台、账号、内容类型、时长与观察窗口，使用可用指标中位数；自我比较排除，同一基线作品重复快照拒绝。每项单列有效样本数，缺失不计零、分母零返回null，不能从无曝光推算点击率，不能从无留存推算完播。`likes_per_view`等字段仅为播放分母的描述性比率，不使用固定综合互动分。无基线或中位数为0时不计算增长倍数。

`followers` 指本作品归因的新增关注数，不是可为负的账号净增；平台未提供该口径时填null。留存曲线、平均观看时长等尚未接入，不能拿互动指标代替它们。

报告保存 `works/<id>/analytics/<version>/<platform>/<p版本>/a0001/`，新观察另建a版本；发布包及ZIP保持固定。没有指标时也能交付 `awaiting_data` 报告，不能伪装成真实平台复盘成功。

内容反馈单独用`--feedback`导入，必须绑定确切manifest SHA，区分`editorial_review`和有来源的`user_feedback`，保留观察、假设、一个主要变量、替代解释与`next_topic`。保存后生成`feedback.json`和`next-brief.json`；后者可直接交回`content-plan`，继承账号与可追溯反馈，选题保持`research`，不自动创建作品。本轮实际跑通的是内容复盘回传，真实平台数据仍缺失。
