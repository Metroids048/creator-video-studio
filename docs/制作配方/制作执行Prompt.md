# 制作执行 Prompt

这是 content-plan 和新工程 prepare 实际加载、冻结并由 plan 返回的执行材料。适用于当前已获授权的任务；阶段授权以用户原文为准。执行者可以是 Codex、Gemini 或其他工具，文件与检查口径保持一致。

你负责给观众一遍能看懂、愿意继续看的作品。目标是第一次给用户看的完整候选已修掉方向、重复、因果、连续性和音乐节奏的明显问题。先消费现有输入与成功工程，沿当前任务工作，不让用户逐版承担内部质检。

1. 恢复本轮要求、保护项、确切父版和已有效阶段。已有参考包、定版音轨、字幕和素材先核身份后复用。输出到当前 brief / task 或原生工程字段，不另造一组必填表。
2. 读 production_method 中的流程、适用配方和工程映射。列清本题“保留的动作/时间函数/相机/分层代码→消费文件→需要替换的事实与资产”。原工程不适配就定位能力缺口；相关真人或图库素材不能替代解释机制。未获制作授权停在本轮产物。
3. 把完整内容落实为对象的前状态→动作→后状态、观众新增理解、镜头承接和结尾兑现。副歌或相似段落必须递进；没有推进先改事件，不能以加速、抖动、标题和快切掩盖。开头与结尾同最难机制一起检查，不能只验中间一小段。
4. 知识歌曲先拿真实主唱乐句与项目基准比较，再制作正式画面。节奏念白只用来试词。冻结歌曲主轨再按实际演唱对词；音乐重音、乐句、揭示、接触和转向共用真实时基。代表段验证箭头语义、全路径遮挡、主体尺度和接触连续性；已认可方向继续复用。
5. 知识歌曲先用有声全曲粗剪检查第一个答案、下一问及最早想划走的位置。再做拟交付规格的开头、最难机制、结尾三段。先遮歌词缩到手机尺寸写下理解，再恢复正常速度声音，核实唱、乐句重音和动作前后帧。明确写下实际看见和听见什么、具体时间、未解决问题。复述不出因果就回修画法，已懂的关系反复出现就比较压短前后，按实际音轨复核争议唱词。
6. 沿 prepare → workflow → plan/make 消费冻结的 Prompt、流程和审片／动效 Skills。把实际歌曲输入哈希、四份媒体、七项具体质量判断绑定到原 task 的 `knowledge-song-preview`。V13 派生工程沿 `native-knowledge describe/check/render/compose` 消费同一阶段。结果待核或已发现缺陷就停在该阶段，只重开相关依赖。
7. 代表段时走通完整审片入口。把声音作为文件交给实际支持听辨的工具，保存原始报告文字。对于整片候选，按正常速度审阅确切版本从首秒到尾秒的画面和完整音轨，另作观众判断并核实外部报告。发现明显问题先内部返修，再同版复审。以观察实际覆盖的范围记录结论。
8. 收尾比较段落是否拖沓，再按曲目需要比较同步变速与理解成本。1.15 仅是本片一次节奏比较。锁定交付版本、审查和可编辑工程后交运营。变速后重新审查确切交付版。

只重开实际变化的依赖与下游；声音、有效录制和未变素材继续复用。保存原反例、父版、原总耗时和费用。相同缺陷再次发生时追查消费入口与方法，不继续无依据改参、重生或刷分。技术检查只证明自身范围，最终观看效果仍须同版观察与反馈。
