# 知识歌曲首版：以《还没落地》V13为制作基准

这是 `content-plan --format knowledge-song` 实际返回的工作材料，适用于不同知识主题。目标是第一次给用户看的完整片就值得作为最终候选。验收看观众能否看懂第一眼的异常、在第一问后还有理由看下去、能否复述因果，以及声音、动作和结尾是否兑现。V13 提供对照；用户认为当前约七到八分，中段负荷和尾段回收仍须改善。

## 基准与复用边界

- 原速视觉/工程基准：`works/falling-footage-1117/candidates/v0013/video.mp4`，SHA256 `78b1e112ea2959f6abebc6592483ad44c5b12a34ab75325c67c3bedffcacea70`；同目录 `editable.zip` SHA256 `3d42e104b786e827ac6fd95c869cb00430bca7a3fbd0ab2e694382002985c871`。复用分层对象、相机、时间函数、字幕和事件组织；新主题先核这些能力是否适配，不把轨道/船舱素材硬套给其他题。
- 用户本轮认可的节奏参考：`works/falling-footage-1117/previews/v0013-speed115/video.mp4`，86.962秒，SHA256 `82dffb27ca5db3f458fe95a92298bd25302aedfe0fa2ce741217bc70645ea05d`。它是原100秒片声画同步1.15倍、音调保留的比较版。其他歌曲不固定照乘1.15，先按实际乐句设计节奏，再比较听感及理解成本。
- 原速完整外部AI审阅在 `works/falling-footage-1117/reviews/v0013/r0001.json`，不是人类直接听审。加速版没有继承该审查；用户正面反馈与完整审查分别记录。
- 参考形式和观看承诺来自本题实际参考，不来自“相关素材”搜索结果；没有完整观察证据时写清已观察范围，不把分镜表当看过原片。

## 一条链上的输入与可消费输出

| 阶段 | 必须消费 | 实际交给下游的产物及判断 |
|---|---|---|
| 参考与事实 | 用户输入、用途/画幅、已有参考缓存、可靠事实来源 | 一个观众问题、一句兑现答案；参考的开头/推进/回收事件与可编辑实现边界。相关题材不等于合适表现形式 |
| 歌词与声音 | 正确解释、可视化机制、已认可音色/音乐 | 已认可歌曲直接复用。新作先试听一组真实主唱乐句，对照基准听旋律、重音与配器，再做正式画面。念白样轨只用来试词。整片前冻结实际歌曲输入，按演唱对齐歌词/乐句/重音；只改画面继续复用原轨 |
| 内容与镜头 | 参考规则、实际乐句、本配方 | 全文因果分镜：每乐句的对象身份、前状态→动作→后状态、观众新增理解、揭示词/拍点、相机与保留项；沿已有 `content_adaptation` 绑定到实际镜头/素材 |
| 最难代表段 | 固定画面形式与完整分镜 | 开头、最难机制/箭头/遮挡、结尾回收的可播放段及实际观察记录；先证明动作可信、解释成立和节奏好，再扩整片。方向已认可不再要求用户重复审批 |
| 首版制作 | 已验证代表段、冻结音轨/字幕、可编辑工程 | 完整候选、源码冻结/素材哈希、事件消费回执、技术检查。先由制作侧修掉明显问题，再给用户看，不能把每次内部修正都交用户验 |
| 审阅与节奏 | 同一候选完整声画、原要求、具体参考 | 从首秒到尾秒的正常播放速度审阅及独立交叉核对；按内容/声音/连续性修正并重审受影响版本。节奏比较在制作收尾前完成，交运营的是确切版本 |
| 运营交接 | 用户认可的确切片、审阅边界、版权/事实来源、受众承诺 | 成片路径+哈希+时长+画幅、审阅记录、封面可用画面、准确标题承诺、禁用表述、待核事项。包装不修改原片、不自动上传发布 |

模型/工具可以承担上述任一阶段，但必须交同样的可编辑产物、实际来源与核验回执。文字建议、生成接单、分数不能冒充媒体结果；不在这里固定 Gemini、Codex 或供应商，也不因此改变当前账号、配置和付费授权。

## 首版必须直接具备的观看效果

1. 开头能看见一个值得问的现象；同一个主体贯穿，结尾以动作兑现答案。副歌重复时至少增加新的参照、状态或机制，不能只换背景、标题和缩放。没有新增理解的长段落优先重写事件，不先堆转场。
2. 图像自己承担解释：在对象上发生运动、对齐、剖开、比较、接触或结果变化。搜索素材先核它与本句因果的关系；真人、NASA或其他题材标签不能代替这层关系。插画采用可分离主体/背景/前后遮挡层，避免把完整图片做滑动相册。
3. 动效跟实际音乐走：揭示/接触/转向落在真实乐句及重音，持续运动保持方向。活泼来自事件、表演和有轻重的节奏；随机抖动、每个对象等幅晃动、固定间隔切镜不是歌曲节奏。
4. 箭头只表达确切物理量或操作：坐标系、起点/终点、方向、标签与画面一致。弯曲只能在语义允许时使用；直箭头表达速度仍可成立。检查整个相机路径中的穿体、遮挡、交叉、淡入淡出和重复指向，能靠对象动作解释就删冗余箭头。
5. 人手与物件先接近再接触，离场/归来有路径；全镜头检查尺度、身份、位置和遮挡。原片中的31–41秒机制段及95.8秒后手套回收是此类检查的反例定位，不是新主题应沿用的秒数。
6. 文字只保留歌词及理解画面必需的标签/数据；不加与内容无关的警示语、“仅供参考”或系统说明。事实边界用准确内容处理，不能依赖免责声明补救误导。

## 交接、审阅与返修沿既有入口执行

`content-plan --format knowledge-song` 返回本文件、执行 Prompt 和 V13 源码复用映射。实际准备输入带 `purpose: self-media`、`content_format: knowledge-song`，`templates prepare` 自动生成冻结的 `production-method.json`，以保留 ID `studio-production-method` 加入 brief.inputs；其中包含正文、来源哈希与13个已核源码文件的映射。`plan` 读取并返回这份冻结材料，`make` 拒绝新自媒体缺方法，导入/恢复继续检查已绑定输入的哈希；editor 路线也校验方法输入。旧任务不因此迁移。

Codex 将方法输入及 `/content_format` 归属原 task，范围显式写入时也归属 `/production_stage`。参考包、事实、歌词、音轨与事件仍进各自阶段。执行者将 V13 的可复用函数映射到本题消费文件，并替换事实与素材。Studio 用 `production_stage: representative` 制作内部短段，整片用同一项目的完整制作简报检查预审。

在现有阶段中加入 `knowledge-song-preview`，依赖此次实际已有的声音与画面设计阶段。该阶段的 `artifacts` 按顺序绑定观察 JSON、全曲粗剪、开头、最难机制、结尾。四个媒体用本次歌曲，三段尽量采用交付规格；全曲粗剪可用草图，但全长声画须覆盖实际制作时间轴。确认阶段用 `workflow <task> --confirm-stage knowledge-song-preview`，用 `workflow <task> --stage knowledge-song-preview` 定位未就绪项。整片 make、恢复与返修会重新核对。

观察 JSON 沿用 `open_issues` 和 `checks`。未关闭问题写明时间及回修阶段；`checks` 仍由 `rough-cut`、`opening`、`mechanism`、`ending` 四项绑定素材 SHA256、状态、时间和观察。`source_audio_sha256` 绑定 Studio 简报的 `audio.mode: supplied` 实际输入，或原生合成的 `approved-audio`。已有带声主媒体的编辑路线使用主视频输入的 SHA256。

在同一文件中记录 `quality`。每项均写 `status`（`pass`、`issue` 或 `pending`）、相对于对应预览文件的 `start`、`end`（秒）及具体 `observation`。当前格式须确认全曲具有歌曲演唱，`vocal.delivery` 如实记 `sung`、`spoken` 或 `unverified`；只有 `sung` 且判定通过才可扩片。已有四项 `pass` 与空的 `open_issues` 仍须过以下判断。

| 观察项 | 对应预览 | 实际判断 |
| --- | --- | --- |
| `vocal` | `rough-cut` | 正常速度对照项目基准，听演唱旋律、重音、配器层次及歌曲和画面的关系。载明实际对照版本和哪些乐句成立 |
| `progression` | `rough-cut` | 记录第一处已懂的结论、第二个问题何时出现。后续每次复现说清新增的结果或参照；只有重复就先压短或改事件 |
| `sync` | `rough-cut` | 遮歌词辨高风险词和相反方向词，记录原始听辨及关键动作重音。存在分歧时用原音轨复听并保留待核 |
| `hook` | `opening` | 手机尺寸先遮字幕，看得清主体、异常、下一句仍值得看什么。留意首次出场和首个组接的残影与跳变 |
| `mechanism` | `mechanism` | 静音先复述因果，再核方向、箭头端点、尺度及全镜头运动路径；开放疑点写明实际位置 |
| `continuity` | `ending` | 正常播放和疑点相邻帧同时核。重点看接触前后、离场/重入路径和连续性；开头和机制段有同类问题也记入各自观察 |
| `payoff` | `ending` | 末尾通过动作或对照兑现开头的问题，核是否提供新结果、能否复述和是否拖尾 |

先记观看和听辨，再对照脚本与标注。有效观察可复用，变化的音轨、时基、源文件或画面重开对应依赖。程序核歌曲输入、文件、时长、区间和记录的判断；事实、听感、因果与审美仍靠实际观察。原纸桥 D/E 复验见[入口复验](../reviews/2026-11-19-纸桥首版失守与入口复验.md)。

V13 派生工程在本任务独立副本执行以下命令。先用 `native-knowledge describe <工程副本> --project <id>` 取方法和当前原生 brief。原 workflow task 保留用户原始 `request`，使用 `action: plan`，引用该 brief 文件并给其字段安排归属。用 `--mode production native-knowledge preview <工程副本> --start-frame <起帧> --frames <帧数> --output <路径>` 从真实场景与音轨取诊断段。粗剪沿现有编辑时间线输出。再用 `native-knowledge check <工程副本> --task <task>` 查预审。整片经 `--mode production native-knowledge render <工程副本> --task <task>` 调用原生渲染器，`--mode production native-knowledge compose <工程副本> --task <task> --output <路径>` 调用其合成脚本。两步共用源文件和阶段核验，输出候选后仍走完整视听审片。历史原生命令保留用于重建旧档案。V13 的 100 秒、25 fps 和 38 句歌词是原片合同，换题须在副本调整合成合同。

旧版实测及漏检定位见[《还没落地》遮盲记录](../reviews/2026-11-19-知识歌曲旧版遮盲初判.md)。

局改先读 `scene-context` 和阶段复用结果，只重开改变依赖及其下游；画面修正保留定版音轨，歌词变化才重新核时间轴，倍速同时改变声画并使旧音画审查失效。不得重跑不相关上游、未知结果的付费请求或已有效录制。

在继续编画面前，用同一句的干声与实际编码后的混音做遮词盲辨。干声也错时先查字头、字尾、乐句重音和上下文，保留原反例，仅替换最短问题乐句并对齐原唱词和动作时间。若仅混音错，先验证伴奏遮蔽能否通过局部混音改善。对仍有分歧的词保留两边回执，无充分复试听感时保持未解决。原生返修工程将独立干声声明为 `composition.json` 的 `dry-vocal` 素材。预审 `quality.sync.blind_check` 的 `dry` 和 `mixed` 记录相对于报告目录的原始 JSONL 文件及其 SHA256。回执行含本版音轨 SHA256、`reference_provided: false` 与实际听辨文本；`unresolved` 记录尚未关闭的分歧。预审、渲染、合成都重新校验这些材料。记录能证明输入和观察范围，实听效果仍须复验。

审片能力在代表段阶段就检查可用入口和完整媒体输入。把音轨文件交给实际能听的工具，聊天工具只回传路径、SHA256 和文字；网页报告直接保存可见原文，避免调用浏览器原生下载。当前已验证的外部AI入口是 `aistudio_full_av_v1`，方法及原回执见 `docs/reviews/2026-11-17-连续画面审阅与返修闭环.md`；仅在获准上传时使用。其他工具须保留同版完整输入、原始回复和独立交叉核对。工具中断后从原阶段和输出恢复，保留待审项。

审片备选入口先用已知动作和音效的代表段验证，例如硬币何时离开纸面、何时触地以及是否听到短促接触声。代表段漏看或漏听，保留失败并停止扩大到整片。正式审片从 `review-prepare` 的 `review_inputs` 取得同版整片和同源独立音轨的绝对路径、SHA256、范围和播放速度，联合审片与独立盲听回执均消费这两项指纹，最后在 `review-save` 复核。入口不可用时继续可做的局部诊断和修复，完整审片保持待验。

审查发现问题则继续本任务返修；审完与质量合格分别登记。程序能核绑定/覆盖/过期，不能自动证明审美。无完整感知的区间如实保留，不能让播放遥测、抽帧或分数替代；用户反馈也不补写成未发生的听审。

下一条获准新题沿本链记录到首个内部完整版、用户首看及认可版各自的时间、费用、整片重做和局部返修次数。以用户是否能首轮采用、还需要指出哪些原可提前发现的问题，验证首版目标。
