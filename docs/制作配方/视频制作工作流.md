# 视频制作工作流：从实际输入到可交付完整片

2026-11-18依据《还没落地》V13及加速版的正面反馈、此前《开箱刀》《今天，就到这里吧》的否决、连续审片入口整改形成。适用于整个制作流程；知识歌曲细节见[专项配方](知识歌曲首版.md)。此次复盘只做跨任务复盘和既有流程优化，未制作新主题视频；以后是否制作沿当次授权。操作授权始终来自当前用户，不来自本文件。

## 每次接单沿一条链交接，不重新发明流程

| 交接 | 当前负责人实际消费什么 | 留给下游什么 | 历史暴露的漏口及处理 |
|---|---|---|---|
| 输入与范围→制作目标 | 本聊天原要求/纠正、作品owner、已有媒体/工程/音轨、参考、用途与保护项 | 原任务中一份有效请求及输入清单，明确这轮交成片、只审查还是运营 | 续做先恢复原状态；不把另一作品/旧维护任务的阶段套过来，不要求用户重填表 |
| 参考→形式与能力选择 | 已有完整参考及观察范围、模板实片/源码能力、旧失败反馈 | 哪些观看效果要复现、哪些素材可换、最难能力与可用实现；明确复用工程层 | 高赞参考/模板数量不等于本地成片合格；NASA相关素材也不等于与唱句有关。先选真实表现机制再做，不因容易渲染换成字幕卡 |
| 形式→内容与音画事件 | 原稿或事实来源、受众问题、参考的推进/回收、固定声音选择 | 完整内容与因果事件：对象前状态、动作、后状态、观众新增理解、相机/声音揭示及回收 | 开箱刀的重复和无效包袱、花场的“有运动无价值”都应在此排除。事件数量不作为内容回报，不为填表编动机 |
| 全文→最难代表段 | 完整因果设计、现有可编辑工程、实际音轨或已知声音条件 | 同一形式的开头/难点/结尾实际表现证据，及必要的技术和审片入口验证 | 最难机制、遮挡、接触、表演或声音不成立，先定位原因再扩整片；已认可方向复用，不强制再向用户索要批准 |
| 知识歌曲粗剪＋三段→整片 | 冻结的歌曲输入、有声全曲粗剪、开头、最难机制、回收实样 | 现有 task 的 `knowledge-song-preview` 同版素材和七项质量判断 | 对照基准识别念白、过早讲完和重复；核手机尺寸因果、正常速度关键词和同步、局部相邻帧及结尾兑现。Studio 和 V13 派生工程在启动整片前拒绝缺项、待核和否决。[原纸桥反例](../reviews/2026-11-19-纸桥首版失守与入口复验.md) |
| 代表段→完整制作 | 冻结内容、已验证方法、定版声音/时间轴、实际资产 | 首个完整内部候选、源码/素材与音轨身份、技术结果 | 内部先修方向/因果/尺度/空转/连续性等明显问题，再交用户。不给用户逐轮验每次试参；声音已认可时画面返修不重唱 |
| 完整片→审阅与返修 | 确切同版媒体、完整声音、参考和用户要求 | 全长正常播放速度的观察范围、具体时间点及问题，独立交叉核对，修后同版审阅 | 技术通过、模型评分、抽帧、播放经过都不等于看听完成。AI与真人分层，审完与质量合格分开；能力限制如实保留 |
| 审阅→制作收尾 | 用户实际收到的版本、认可/否决、实际节奏与阅读成本 | 确切MP4及可编辑工程、版本/哈希/时长/画幅、审阅与认可范围、总耗时/费用边界 | 节奏比较在此完成；变速同步声画并使旧听审失效。不覆盖父版、不用新版本重置时间或隐去失败 |
| 制作→发布前运营 | 确切片及身份、受众承诺/事实来源/可用画面、未验事项 | 封面/标题/正文/标签/互动、预览与离线包、后续真实数据观察方案 | 制作和运营分阶段；包装不得反向夸大内容，不自动发布。数据复盘以真实数据为准，制作流程复盘不索要不存在的播放数据 |

## 模型可换，交接对象保持一致

模型负责解释、策划、画面代码、图片、声音或审查中的一项时，下游接收**实际可消费产物**，而不是一段“完成了”的消息。每次交接保留：要求/方法版本、输入与输出路径及哈希、实际任务/回执、当前已验与缺口、下一允许动作。软件选型由当前可用能力和授权决定，不在流程写死Gemini/Codex型号，也不自动切换账号、读取凭据或扩大付费范围。

优先消费项目已有内容策划、研究、设计、原生编辑/动效、审片、发布与复盘Skills。缺的是方法消费或媒体验证就修这一层，不因缺口另起完整框架。声音模型与审查模型的风格判断不是用户验收，来源中的方法建议也不是经过实测的质量结论。

## 用现有执行入口约束复用和返修

1. `intent` 判断本轮阶段；`content-plan` 返回本方法全文/哈希、内容资源及历史反馈。工作流复盘现在进入framework，真实发布数据复盘仍进入analytics。
2. 新自媒体 `templates prepare` 将执行 Prompt 与方法正文自动冻结为 `production-method.json` 输入；知识歌曲用 `content_format: knowledge-song` 连同 V13 源码映射绑定。`plan` 实际返回冻结材料，新 `make` 检查不得漏带；输入导入与恢复检查沿同一素材哈希。负责人给方法输入归属现有阶段，把参考包、脚本/事件/声音等产物加入原 `task.json` 对应阶段的 `artifacts`；沿 `workflow --stage` 取可复用结果，再用原阶段确认/重开。`content_adaptation` 对应真实镜头和素材；不新增第二条状态链。
3. 局改用 `scene-context` 找最早变化依赖，只重开该处及下游。失败先与父版具体反例比较；没有新因果依据不继续同类试参、重交未知付费请求或推倒有效上游。
4. 原生工程沿自身恢复和冻结入口。V13 派生工程用 `native-knowledge` 消费共用预审并调用原生渲染和合成，结果保留为待审候选。未接入阶段交接的其他独立路线记录自己的版本、锁轨和同版审阅。
5. 当前完整外部AI审片沿已实测 `aistudio_full_av_v1` 和[真实回执边界](../reviews/2026-11-17-连续画面审阅与返修闭环.md)复用；其他方法必须有同版完整输入/原回复及独立核对。代表段就检查审片入口。音频交给支持它的工具，聊天只接收路径、哈希和文字。浏览器返回报告后直接留存可见原文。[实际中断与文件交接](../reviews/2026-11-19-纸桥中断与恢复.md)

这套接线检查能保护已绑定的版本/依赖，不能强制任意工具都走入口，也不能自动判断作品是否有趣。执行者仍需实际观察内容、画面和声音；不能以记录齐全自我放行。

## 本次收敛到什么，后续用什么衡量

V13作为“信息持续推进、因果图像成立、动作连贯、动效随音乐、文字服务内容”的质量参照，加速版作为本次短视频节奏参照；不把100秒、船舱、箭头或1.15倍变成所有作品模板。

目标是第一次交付的完整片就能作为最终候选。以真实作品记录首个可比较的主唱乐句和难点样片、内部完整版、用户首看及认可版的时间；墙钟沿首次接题，分列中断、已知工具运行、可归因的返修、费用、整片重做和用户实际承担的返工。记录缺失保持未知；质量和速度的提升以真实首版复测。
