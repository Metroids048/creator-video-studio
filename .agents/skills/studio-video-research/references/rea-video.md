# 用 rea-video 拆片包衔接工作室

适用：指定参考链接、形式复刻、知识歌曲/说唱拆解，或已有 rea-video 输出要交给策划、分镜和剪辑。先复用已核验的参考研究。源码研究不替代完整音画观察；没有拆片包时直接沿现有研究方法工作，不为采用工具重新跑旧片。

来源：[JuneYaooo/rea-video](https://github.com/JuneYaooo/rea-video)，固定提交 `ebe853e330d63719a1f91754f789647c515eac19`。选取的源码和许可证保存在 `sources/rea-video/`，校验见 `source-manifest.json`；本项目未安装其运行时、模型权重或生成后端，也未注册它的宿主 Skill。源码 Apache-2.0，权重另有许可，不能混用结论。

## 输入和实际读取入口

上游 CLI 的输入是本地视频文件，未提供抖音链接解析。本工作室先核原帖、合法可用完整源文件及完整音轨、已有观察记录与哈希，缺失照实标注；本方法卡不会自动下载或上传。

已有拆片包含 `VIDEO.md` 和 `breakdown.json` 时，用只读入口：

```sh
python3 scripts/studio.py reference-inspect /绝对路径/拆片包
python3 scripts/studio.py reference-inspect /绝对路径/拆片包 --topic timeline
python3 scripts/studio.py reference-inspect /绝对路径/拆片包 --topic sound
python3 scripts/studio.py reference-inspect /绝对路径/拆片包 --topic cast
python3 scripts/studio.py reference-inspect /绝对路径/拆片包 --shot 7
```

只读取需要的卡片、专题或单镜文本，返回文件 SHA256、生产者记录、逐镜降级标记和交接文件路径。不导入上游 Python、不调用模型、不运行其 `remake/code-remake/assemble`，不确认任何工作室阶段。原媒体并未由此入口校验。`breakdown.source.sha256_head` 只覆盖前64MiB；上游 VIDEO.md 若记录完整哈希，应另与原媒体核对，不把前者当完整指纹。

`whole_ok`、有全片模型回答、ASR成功、测得BPM都不证明完整音轨被感知。上游逐镜可退到 `mute_clip` 或 `frames_only`，单次镜头分析亦有时长/次数上限；本入口一律保留 `complete_av_verified=false`。完整视听的证据沿项目原记录单独核验，不能把检测数据或模型概述升级为Codex亲自/真人完整听审。

## 交给现有阶段什么

| 读取内容 | 消费位置与输出 | 保留边界 |
|---|---|---|
| VIDEO.md、content、timeline | P1/内容策划：参考的观看承诺、因果段落、固定形式及换题边界 | 既有选型有效即复用，不重搜/重拆；观察与推断分列 |
| cast、单镜 | P2/D1/D3：角色职责、对象状态、完整动作和镜头承接 | 声部ID与画中角色ID分开；新主题事实和行为重新设计 |
| sound | P3/D5：声部、乐段、解释唱段与记忆句的功能；可用的节拍/词时标 | 数值是测量/模型结果，不自动认可听感；原曲不默认可沿用 |
| look、packaging | P2/D4及原编辑工程：可变素材、字体、字幕与画面层关系 | 字幕依定版新音轨重定时，不能照搬原片绝对秒数 |
| remake、单镜 | 原模板/编辑路线：组件、输入、方法缺口和最难段 | 方案/Prompt不等于已有可编辑模板，也不自动取得市场或生产资格 |

`reference-inspect` 的 `handoff.artifacts` 是本次消费的卡片、机器记录和所选文件。由Codex加入**已有 workflow 对应阶段**的 artifacts，按实际字段/needs建立依赖并沿原入口确认。其余专题只列目录，不应全部塞入每个阶段。修新片的某镜时复用参考、已定歌词、定版音轨和有效素材；沿 `scene-context` 读取该镜及相邻事件，只开放最早变化的依赖。不因改字幕/局部画面再拆整片或重写整曲；歌词确实改了才回歌词及其声音后继。仍是一条 Active 链，不新建 rea-video 状态系统。

## 知识说唱怎样用

按“可核查事实/因果 → 可唱句 → 音乐段落/声部 → 画面对象状态 → 镜头事件”对应。每行保留来源、参考范围、解释目的、唱句功能、声部职责、对象开始/动作/结果、需看清的动作及下一镜承接。事实有依据才能进入歌词；押韵不能改变机制或丢掉条件。

运冰参考的可迁移关系：热带运冰难题 → 储运损失 → 规则冰块/表面积 → 锯末与空气隔热 → 融化吸热 → 港口买卖 → 制冷技术取代。知识推进可以跨多句和多镜，不每拍切镜，也不把科普改成只剩历史人物的舞台表演。现有完整音轨研究认为男女声承担讲解交替；Tudor是故事人物，不能仅因其出现在画面就给他分配同一声部。原片BPM未核实，留空。详见 `docs/research/2026-11-15-原片源码与工作室复盘/万有音律完整音轨与音画结构.md`，该记录为外部模型研究，保留其感知限制。

固定栏目可以保留视觉语法、角色职责、解释段/记忆句交替和声音反差；新题必须重做事实、句子、乐句长度、对象和因果动作。最终歌词与音轨冻结后，再把其时间标记绑定到已有 `content_adaptation` 的稳定单元/镜头；没有定版音轨时用语义乐句定位，不伪造精确秒数。

交给Codex的消费提示词（用于P1–P3，不意味着新增三次模型调用）：

```text
先读原workflow当前阶段和已有参考证据。有效结果直接复用。
按需读本次拆片包的timeline/content/cast/sound及目标单镜，不重新分析全片。
保留真实观察、信号测量、模型推断和未知的来源差异，静音/图片降级不算完整音画。
把本题事实—唱句—音乐功能/声部—对象状态—镜头事件对应；说明什么固定、什么随内容换。
只更新当前失效字段，列本次实际消费文件供原stage_handoff绑定；不改其他有效阶段。
声音/角色/物理机制尚无成熟实现时指出具体缺件，不用复刻Prompt或像素相似度宣告成立。
遵守本轮授权；研究与设计不自动生成歌曲、视频、上传或发布。
```

## 尚未接入的能力

rea-video 的完整分析运行时、抖音取源、音画连续输入的宿主适配、中文说唱音质/咬字修复、自动事实核查、任意机制动画/角色表演和批量生产都未由本次接线证明。上游音乐来源推断带先验，不能认定某片使用Suno；分轨可能损伤混音，不能当独立原始人声。其代码重画限于可参数化对象，拼装可保留原镜/原音轨，不应充当新作品。后续只有具体授权、固定输入和真实效果验证才能采用运行时。
