## 2026-11-15参考方法的实际使用

先全时段内容与完整声音，再定位具体时间码；分别标明外部模型、实际播放、真人和用户认可。检查知识事实与歌词、字幕与实音、声部与角色、动作与音效是否对应，查看中段和结尾是否兑现开头；声音存在或全帧可解码不证明观察完成。Fred来源/调用检查与OpenFilm测量仅辅助定位，SSIM/运动量/切镜数不判质量。局部失败只重开受影响依赖，保留父版和原反例，不以评分循环替代改进。

具体证据及边界见[七条参考与源码复盘](../../../docs/research/2026-11-15-原片源码与工作室复盘/研究总览.md)，执行沿现有[P1–P6](../../../docs/research/2026-11-13-后续制作方法与Prompt.md)及[制作流程](../../../docs/制作流程.md)。这些为当前Skill执行指引；除明确列出的CLI检查外，不声称已实现自动质量拦截或新增生产能力。


输入为作品 ID、确切版本、产物哈希、锁定项和可用审查证据。输出收敛为[三份主记录](../self-media-studio/references/审查与版本.md#一次审查的三份主记录)：审查包 `frames.json`、交叉核对表 `cross-check.md`、最新同版结论 `rNNNN.json`。原报告、帧、音频、遥测和诊断脚本作为附件，draft 为工作稿，历史修订保留。每条发现记录层级、时间区间、观察方法、影响、修复目标和复验范围。

先应用[观众视角与制作避坑](../../../docs/观众视角与制作避坑.md)。正常速度、小屏、暂不看工程解释，按实际开头/推进/兑现区间记录为什么停下、继续、得到什么及最强划走理由；氛围片核画面/声音本身能否持续成立，不强制剧情或快切。实际内容或观感不成立记content/visual=issue、finding=open；未观察记pending。动作子问题改善不得把整条吸引力投诉标resolved，不能把基础质量责任推给用户认可待验；AI编辑判断与真实用户/平台反馈分别记录。沿既有review-save/status/export，不新建自评分闸门。

- 先从`status`核`current_role/delivery_ready/quality`；current是活动候选，`reviewed_candidate`也不等于真人或用户认可。审查材料准备失败保留父版与pending；已有候选可在具体续做授权下resume复用，不重渲染。
- 用 `../self-media-studio/references/审查与版本.md` 执行同版审查。`make/resume/restore/revise-*` 完成后自动抽取全片2fps原尺寸帧；既有版本先 `studio.py --mode development review-prepare <id> --version <v>`，恢复复用原包，不重新生成替换问题记录。
- 从 `review-prepare` 的 `review_inputs` 读取同版完整影片与独立完整主音轨的路径及 SHA256。独立音轨对应 `frames.json.audio_review`，AAC 原流，其他格式无损 PCM，多音轨只提取首条。有上传授权时使用这两项实际文件，联合审片与独立盲听回执由 `review-save` 核对同一份提取音轨。旧冻结包保持原输入核对方式。先核真实模态、完整范围和末尾声音。提取和播放证据只覆盖交接与传输。
- 正式审片端未验证时，先查后台入口是否能到达；候选工具用已知动作和音效的代表段核实际感知，漏看接触或漏听音效就保存反例，不扩大到整片。文件交接只向 Codex 返回路径、指纹和文字观察。不得通过聊天工具回传原始音频。
- 画面被反馈为PPT或衔接不自然时，按[连续画面审阅与返修实例](../../../docs/reviews/2026-11-17-连续画面审阅与返修闭环.md)核实际运动、转场和主体；外部审片核完整时段及实际采样设置，报告返回后继续同版反例返修与复审，不停在“已上传”或“待审”。真实授权、免费设置、模型感知边界分别记录，不伪装连续人审，不修改检查取得放行。
- 有外部报告时在核对表逐条对照实际源码、成片和独立音轨，写采信/丢弃/待核对及证据；实际演唱有分歧须盲听，不按目标歌词猜。采信的问题进入 issue/open findings，未核实保持 pending。保存结论前绑定核对表及附件 SHA256；助手观察单列，不作放行评分。没有外部报告说明缺口，不伪造审查或自行追加付费调用。
- 打开审查包的全部拼图，再打开文字最长、转场和关键动作的原尺寸帧；在包内 `draft.json` 逐帧记录 `pending/pass/issue`、实际观察和证据文件SHA。正常速度连续看完整原片，分别记录视觉、内容、连续播放、真实听审的完整范围；无听觉能力保持pending，不用声学检测或视觉代听审。有问题先保存失败结论并告知用户；不等用户使用后再暴露。
- 用 `studio.py --mode development review-save <id> --version <v> <draft.json>` 留下不可覆盖的r修订，再 `review-status`。核 `review_completion/quality_status/observation_scope/observation_limits`：审完有问题保持 issue/open，不能继续叫待审，也不能冒充合格。程序只核绑定、覆盖、记录结论及历史问题，审美仍由真实观察负责。`review-check`兼容旧记录，只证明归属，不能授权交付。
- `export`、`publish-check/publish-pack`、导出workflow共同消费上述同版结论；缺审、过期、待审、未解决问题均停止。直接读取原片只作明确标记的诊断预览，不以Markdown附件绕过闸门。真人或用户认可单列，不伪造为前置已通过。
- 按场景采用 `resources/mg-styles/rubric.md` 的时间码和具体改法，或 `runtime/avs/skills-src/quality-review/SKILL.md` 的 Episode 质量核对。脚本或配置改变后，按实际依赖使旧观察失效。
- 返修交给主 Skill 的局部补丁流程。候选失败保留父版与回执。没有必要视听证据时，先列待审范围，不用静态结果宣布效果通过。
- 对照 `docs/research/2026-11-13-后续制作方法与Prompt.md` 的P5–P6，连续看听完整同一版；比较参考的同一语义段落，而非只看总时长、配色或抽帧拼图。覆盖开头兑现、所有转场、关键动作连续帧、中文阅读、音乐段落及实际导出的封面。无配音片仍须真实听审BGM与SFX。
- 人工视觉、人工听觉、AI观察和程序检查按 `../self-media-studio/references/审查与版本.md` 分开记录。人工条目须有真实人员、版本／哈希、观看或听审范围、结论及实际反馈证据；没有发生就待验，不由模型填写“人审通过”。人审待验不替代已授权制作，可先完成整片候选并明确缺口，不自称已达七八分。
- 发布包只整理已核对版本的本地附件、标题、字幕、素材许可和反馈字段。发布另需明确授权；当前框架仅做只读审查与交接。

本片实例见`docs/research/2026-11-13-v0009视觉自评与情绪动画竞品复盘.md`：抽帧可读不代表正常尺度动作可读；核字幕是否先于实际事件泄露结果；音乐无爆音不代表音色／乐句贴合。用户要求自评分时允许给明确主观评分与时间码依据，但不把它写成真人验收或流量保证。片长按动作、阅读和乐句确定，不为凑60秒重复事件。

六维审查调用 `docs/research/2026-11-13-六维方法与Prompt.md` 的D1–D6，对照同目录 `2026-11-13-v0009不渲染走查.md` 的E5–E7实例：正常尺度看意图／支撑／回望，字幕相对可见揭晓，后段是否新增信息；声音比较同画面与近似感知音量，封面核真实平台遮挡及导出对象。相机／动作／音乐变更后按依赖更新对应观察，不沿用旧秒数和旧听审。小红书原片、声音实听和平台裁切缺口见来源索引，未观察不能标通过。研究方案可解释不等于实际效果已验。

`continuous_review` 的当前有效格式和限制见上方入口文档。外部 AI 必须保留原始报告及其局限，消费实际 `aistudio_full_av_v1` 附件回执；仅方法名、评分或自述不能取得资格。浏览器上传仍由 Codex 在有效授权内操作，程序不上传、不调用模型，也不自动认证感知或审美。真人反馈和用户认可不得由模型代填。
