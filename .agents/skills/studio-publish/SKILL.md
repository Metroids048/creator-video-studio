封面概念、排版和素材选择衔接 [studio-visual-design](../studio-visual-design/SKILL.md)：先定主体/信息/强调层与参考图角色，消费 `visual-assets` 的实际字体、纹理及许可；再沿下文既有图片供应方与逐图观察入口。方向板不能替代最终封面或实际观察。

内容理解、标题与封面的分工、缩略图检查及留存诊断沿[从片内回报到标题封面](references/内容到封面.md)。先找到片内具体动作和兑现时间，再出图；不默认强调歌曲/动画等形式名称，不从第三方运营技能继承发布权限或流量承诺。

## 2026-11-15参考方法的实际使用

只消费通过既有交付条件的确切成片版本与哈希再包装；标题承诺必须能指到片内兑现处。作者身份/IP、声音、歌曲和参考素材的使用权分别核，不能从开源代码许可推导媒体许可。参考作者的播放量、产量和耗时不进入本工作室收益承诺。平台发布仍按本次授权；本轮仅方法整合，没有发布或新封面制作。

具体证据及边界见[七条参考与源码复盘](../../../docs/research/2026-11-15-原片源码与工作室复盘/研究总览.md)，执行沿现有[P1–P6](../../../docs/research/2026-11-13-后续制作方法与Prompt.md)及[制作流程](../../../docs/制作流程.md)。这些为当前Skill执行指引；除明确列出的CLI检查外，不声称已实现自动质量拦截或新增生产能力。


先用 `scripts/studio.py intent '<原话>' --profile publish` 核能力包。具体合同和已跑通案例见 [发布与复盘](../../../docs/发布与复盘.md)。

实际schema 3新包参考[等消息p0002](../../../productions/operations-integration-20261114/message-p0002/交付说明.md)：包括两种概念、B首稿裁切失败→同工具重排、真实生成记录、缩略图观察、ZIP及复盘回传。只复用方法与数据形状，不复用该case标题或把它当品质范本。平台裁切与真人听审仍待验，底层模型未暴露为null。

执行前按 [受众到复盘](../self-media-studio/references/受众到复盘.md) 读取共享账号与本条选题，运行 `content-plan`。先展开六到八个角度再筛三个标题，封面先写两种不同的视觉概念再出图和审图；不能抄开发描述或用三个同义改写充数。新 spec 必须绑定 strategy、承诺的片内时间、逐项标签依据及两张封面的实际观察；publish-check/workflow/publish-pack 共用真实检查入口。旧包可校验，新建不能回退到无策略模式。

1. 读取指定 `works/<id>/versions/<version>` 的 `brief.json`、实际视频、原脚本与回执。先核 `review-status`；待审／问题先交 `studio-video-review`，不要用新封面掩盖旧视频缺陷。新 `publish-check/publish-pack`强制消费同版全片审查，旧包 `publish-verify`仍可只读核验并显示当前视频质量。抽帧、浏览器播放、模型观察、真人听审分别记录。无明确版本先查 `status`，不切换 current。
2. 围绕真实受众和内容承诺，给三个不同角度的标题及推荐理由、两个有实质区别的封面、最终公开正文和相关标签。公开简介须重新写，不能抄开发 request。热点依据未知就不附热点。标题、封面和开头必须能相互兑现；不承诺流量提升。
3. 封面选择先读[封面研究与采用](../../../docs/research/2026-11-14-封面研究与采用.md)，按本条受众和处境重新找相关高播放/高赞原帖，并保留普通或不采用的比较。实际打开封面，记录原帖、指标类型/日期、视觉观察、适用性与限制；没看到封面的帖子只能列候选。点赞不冒充播放，跨平台经验不冒充抖音验证。借鉴表达与构图，不复制原图或作者肖像。
4. 最终封面使用 Codex 宿主 `image_gen.imagegen`，明确请求 `Codex Image 2`；SVG/Chrome仅可做草图，不能作为新包的最终封面来源。不启用其他模型回退。工具未暴露底层模型就记录 `reported_model=null`，不能自称已核实Image 2。保留作品视觉关系、原始画幅，竖封面单独排版；实际看生成图片、小屏与裁切，未知平台安全区仍待验。
5. Codex 写 `spec.json`（字段见文档）：除策略和承诺外，必填 `cover_research`、逐封面 `generation`、五层 `review.checks`。`publish-check`、`workflow publish`、`publish-pack`共用检查；新包schema 3固定这些记录，不能用旧schema绕开。经交接核验后执行 `--mode delivery publish-pack`。未变视频、音轨与素材复用，不因改包装重跑制作。
6. 打开真实 `preview.html`，看选中封面、标题、文案和完整视频；`publish-verify` 核对产物及质量摘要。离线可用和质量待验分别显示；程序只验记录/绑定，不能认证模型调用、审美、人审或流量。封面/文案变化用新 p 版本；视频变化重核来源，不能更新旧回执让旧审查继续有效。保留原制作文件和指针的哈希证据。

本阶段止于完整离线包及 ZIP。账号、公开范围、时间未设置；任何平台当前字段限制或裁切尚未验证即标待验。后续接入 Aitoearn 等通道必须另有用户授权并复核真实工具合同，不能从本 Skill 推出发布权限。
