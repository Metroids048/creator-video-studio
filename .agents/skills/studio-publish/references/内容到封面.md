# 从片内回报到标题封面

用于已有成片的包装，也供选题、脚本与分镜开发反向核对。先读确切作品，不从“太空、职场、情绪”等题材名直接出海报。已有工程、声音与发布授权沿主流程，本方法不新增制作或发布许可。

## 先弄清观众为什么要看

在本条已有工作文件中写清：观众看见什么具体事情、直觉如何判断、片中哪个证据改变判断、看完能回答什么。至少区分开头的问题、中段新增的信息、结尾的兑现。给承诺标注确切成片时间；字幕、脚本与抽帧只辅助定位，不能替代完整视听。

沿已有 creator-workflow 的 audience/problem/stakes/signal/promise，消费账号与单条选题；沿 ip-strategist 的“需求×方案”和信息递进判断切口。知识片先核事实和解释，剧情核选择与后果，歌曲核歌词、音乐段落与画面怎样共同推进。不把所有内容套成同一种冲突故事，不借“爆款公式”替代实际判断。

## 标题和封面各承担一件事

- 先展开六至八个真正不同的观看角度，再筛三种。区别应在问题与回报，不能只是同义替换。
- 先写两种视觉概念，再调用既有宿主图片工具。优先从片内关键动作、物件关系、前后变化中提取；两图要改变主要表达，不能只换颜色。
- 标题补充封面缺少的场景或原因。封面用一个最先读懂的关系提出问题或呈现关键发现；避免封面、标题、开头把同一句话说三遍。
- “一首歌”“动画”“AI制作”等形式名称只有对本条受众有实际选择价值且用户允许时才写；默认先说内容。本片用户明确否决形式标签，必须删除。
- 设问应由实际内容兑现。夸张表情、危险箭头、虚构冲突、无重力图示或与片内不一致的对象，不能为吸睛加入。

## 看最终图，留下逐图判断

实际观察原图、120像素宽缩略图及目标裁切；检查中文、主体、动作关系、信息层级和四边。模拟正方形、竖屏裁切不等于平台真实安全区。概念不成立时先改表达，不只加大字体；修改后重新绑定最终图片哈希和观察，父版失败保留。发布仍沿 publish-check → publish-pack → publish-verify，同版视听缺失不能由封面通过补足。

## 内容与运营复盘相互反馈

首屏流失先检查封面承诺是否被开头接住；中段流失检查是否重复、解释停滞或视觉没证明歌词；结尾检查承诺是否兑现。以上是诊断假设，需要真实数据和反馈支持，不能从一个指标直接判原因。比较同账号、相近主题与流量来源；不采用统一CTR/完播阈值，不预告增长比例。没有发布时只保留观察安排和空白数据表，不编造结果，不同时改多项后宣称单项有效。
