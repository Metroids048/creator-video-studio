# 创作与选路

接收用户原话、现成素材及必须保留的事实、操作、声音或画面。先归纳观众、想传达的信息和最终交付，推断一般创作选择并记录假设。仅在关键信息无法替代、素材权利不清或需额外费用与外部操作时集中提问。把账号、题材和风格当作可验证假设。

2026-11-15最新原创要求：先按[原创内容开发](原创内容开发.md)完成构思、具体内容和粗略镜头/表演，再沿现有目录选择实现工程；不由纸墨走路等易做底座倒推故事。`content-plan`直接提供当前反馈正文与方法。指定改编、完整稿、原生恢复和局部返修保留原合同，不另起原创。

## 研究

读取 `sources/zh-explainer/skills/reference-style-video/references/reference-research.md` 和 `production-lessons.json` 中与任务相关的条目。逐条记录原出处、时间码、观察范围、实见动作与声音、推断及反例。仅见截图或文字时写明证据范围。把可迁移规律改写为原创镜头约束，保留可追溯引用。输出方向、表达规律、候选假设和风险。`research` 在研究交付停止。

## 策划、分镜与交接

项目方法沿用 `docs/research/2026-11-13-后续制作方法与Prompt.md` 的六段Prompt。原创内容发展在前；工程选择后再绑定“原场景文件→保留能力→替换资产→新增适配”，把已经明确的内容转成可执行事件，不让工程能力倒推内容。旧下一任务交接按其历史范围保留，不恢复制作授权。

脚本按事件、信息和转折划分。每镜写起始状态 `preState`、主体动作 `action`、画面结果 `result`、观众能获得的信息 `takeaway`，再写镜头时间、声音、构图、路线和需要实查的条件。这些是分镜说明，可随原生项目保留；本地 brief 的 `shots` 只接收执行所需字段。机制镜头标出主体、作用对象和接触前后，故事镜头标出角色目标、变化和后果。给了录屏就把不可丢的操作、源时间码和原音先列为锁定项；给了完整稿件就以稿件为基线。歌词或无对白故事用节拍、音轨和动作承接信息。

连续性写在同一份分镜／原生工程说明里：主体造型与尺度、空间／道具位置、运动方向、镜头结束与下一镜起始的状态、字幕阅读区、音乐乐句及音效事件。不要另建平行状态机。完整内容先有开头承诺、发展、转折和落点；无配音脚本是屏幕字幕与画面事件的配合，不是把旧口播全文贴进画面。音乐选定后统一镜头、字幕和声音的时间基准，变更剪辑需重映射成片时间。
