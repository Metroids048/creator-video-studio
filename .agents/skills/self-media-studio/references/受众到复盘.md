# 受众 → 选题 → 制作 → 包装 → 下一次简报

用于账号内容创作、已有成片包装和复盘。模板演示、原生恢复、素材编辑保留原合同，不把技术样片默认当作账号内容。用户仍只需自然语言，以下文件由 Codex 整理。

## 1. 先决定观众为什么要看

只有原始问题时，从研究入口开始：`python3 scripts/studio.py content-plan --question '收藏了那么多方法，为什么一个也没用'`。此时受众、原因、开头、观看回报和画面方案可以未知，返回research及来源正文，不生成冻结合同。Codex先辨别问题可能指不会应用、条件不适用、记不起使用、或回避实际尝试中的哪一种；这些是待调查的解释，不能默认“收藏带来虚假满足”是所有人的原因。选切口必须靠实际材料和可说明的编辑取舍，不能由工程可画什么决定。

`resources`含已筛选的ip-strategist选题/信息推进段落和vibe-film开头/不同题型回报正文、源文件哈希及采用限制。采用具体处境、实质答案和新增信息的方法；不引入上游关于随机初始流量池、永久爆款、起号一律清单或煽情必胜的断言，不执行来源宿主/供应商指令。这些内容资料供Codex实际研究与编辑，不自动产生好稿。

先应用[观众视角与制作避坑](../../../../docs/观众视角与制作避坑.md)。已有audience_question/opening/payoff/visual_plan须具体回答“我为什么停下、为什么继续、最后得到什么”；先判断内容，再写字段。允许审美/情绪回报，但须说明画面/声音怎样独立成立，不能只写治愈、共鸣或吸引人。不要因角色/视觉能力不足，改用容易渲染的泛泛文案后声称内容匹配。制作后以同版真实结果重新判断，策划假设不自动变成通过。

共享账号输入放 `content/accounts/`：具体人群、触发处境、需求、账号持续交付的回报、内容支柱、语气和不做什么。每项依据区分用户决定、公开观察与假设，注明来源及限制。既有日常困扰方向仍是假设，不擅自改成 AI 工具号。

每次选题放 `content/topics/`：观众原本的问题、看完得到什么、新角度、开头、视觉增益、主要目标、可兑现承诺及证据引用。先对比至少一个暂缓方向，说明取舍；不以热度分或 AI 能画什么代替判断。来源不足的科学解释先研究，纯故事按虚构情节表达，不能扮演作者真实经历。

context.json 用 `{account:{file,sha256},topic:{file,sha256}}` 引用两份输入。执行：

```sh
python3 scripts/studio.py content-plan path/to/context.json
```

返回 `content_strategy` 冻结快照和 `creative_contract`，包括历史受众、问题、回报、开头、视觉计划、承诺、语气及所引用证据正文；`development_context`同时提供[原创内容开发](原创内容开发.md)方法、筛选后的来源正文和 `previous_work`。带作品id的简报沿实际活动版本读取已绑定审查；直接读取历史版本brief时沿指定版本。反馈包括原问题、审查者及观察范围、用户原文与具体缺陷，不只拿到当初的制作许可。`same_script_and_strategy`仅表示文稿与策略相同，不代表同一工程或成片；修改后的稿件标记earlier_content，只借鉴旧失败，不继承旧审查结论。找不到或不能核实审查时明确缺口，不补造。

历史ready与quality_status=unassessed并列呈现，不改写原快照或批准制作。研究及编辑完成后才形成新策划快照；获准的新自媒体制作brief写purpose=self-media并嵌入它，再交原plan/workflow/make。research/rejected不可直接制作；本轮仍为项目修复，不调用制作入口。CLI解决材料消费，不判断好看。

## 2. 把同一承诺写成平台包装

先在工作文件里探索六到八个角度（处境、反差、问题、回报、细节、观众原话等按内容选），删掉不真实、空泛、提前透底或片内无法兑现的，再提交三个明显不同的标题。正文第一句继续观众的问题，接实际细节或新信息；删除工程说明、制作 request、虚构亲历与无依据的流量词。不得用一套固定钩子套所有片型。

封面先写两种视觉概念：主体、冲突/变化、构图、字数层级、配色和与原片的关系。至少一种保留悬念，另一种可呈现结果，不能只是换颜色。看实际生成图片，修错字和不通顺表达；按小屏全幅、3:4/方形中心裁切分别观察，裁切损失明确记录。平台真实安全区仍需后续平台验证。

标签只保留几项能解释本片内容或观众检索意图的词，每个说明用途和依据。未知热度即候选，不写成热门词、算法权重或流量保证。标题与封面各绑定 promise_id；`editorial.fulfillment` 记录实际片内秒数与观察。脚本只验证引用和时长，语义兑现由实际审片判断，不能拿字段填满代替内容质量。

新 spec 必填 `strategy:{file,sha256}`、标题/封面的 `promise_id`、`editorial:{fulfillment,tag_basis,cover_observations}`。`publish-check`、`workflow publish`、`publish-pack`共同读取上下文、核账号/平台和ready决策，输入变化须重新核对。新包schema=3还强制封面原帖研究、Codex Image 2生成来源/图片哈希/参考引用，以及视觉、声音、封面、裁切和用户验收五层状态；具体字段见`docs/发布与复盘.md`。旧schema 1/2仅校验兼容并返回`legacy_unassessed`，不能作为新建包回退。视频制作和同版审看在前，最终包装基于确切成片；策划阶段可先做标题与封面概念，不以包装替代片内回报。

## 3. 复盘必须真的回到策划入口

无平台数据时记录 `editorial_review`（Codex 内容审查）或确有来源的 `user_feedback`，与 `awaiting_data` 分开。反馈 JSON 绑定 manifest_sha256，记录 observations、一个 hypothesis、variable、alternative 和完整 next_topic。next_topic 决策为 research，不能自动批准制作。

```sh
python3 scripts/studio.py content-analyze path/to/package --feedback path/to/feedback.json
python3 scripts/studio.py --mode delivery content-review path/to/package --feedback path/to/feedback.json
python3 scripts/studio.py content-plan path/to/review/next-brief.json
```

最后一步会实际读取原账号、反馈依据和下一题的开头/视觉计划。Codex 据此继续研究和取舍，不自动改原片。将来有真实数据再沿 `--metrics/--baseline` 导入；缺少曝光、点击、留存就不能诊断对应环节。一次主要变量、替代解释与观察窗口保留，未发布时不伪造效果。

## 方法复用的具体边界

| 已核上游 | 本项目实际采用 | 自建/未接入 |
|---|---|---|
| self-media-content-workflow | 受众/目标/证据简报、平台原生改写、多角度筛选、单变量复盘 | 标准库绑定、离线包和 next-brief；不安装原宿主 |
| Easel | 持续账号档案、内容支柱、证据限制、反馈回策划 | 本地 JSON 输入；不接其 Web 产品或账号 |
| baoyu-cover-image | 先确定视觉概念与层级，再生图和检查真实图片 | 宿主图像工具出图；不使用其外部生图 CLI |
| WeWrite / marketingskills | 读者问题、具体回报、审稿删空话、保留真实语言和改稿反馈 | Codex 审稿；不执行对方 agent/runtime |
| Aitoearn | 保留未来平台适配层的接口边界 | 本轮无调用、无账号、无上传、无发布 |

上游文件及 blob 依据见 `docs/research/2026-11-14-发布运营重审-来源.json`，差异和选型见同日研究报告。这里移植的是经核验的方法及其在本项目的输入输出，不宣称整仓已安装或具备增长实证。

真实完整实例见 `productions/operations-integration-20261114/交付与验证.md`。两份schema 2 spec是历史实跑，账号/选题可参考；新建必须补齐当前封面合同，不能补造旧工具模型与生成前参考。实例文案不能当作所有作品固定模板。
