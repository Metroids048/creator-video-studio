# 审查与版本

内容与观感先按[观众视角与制作避坑](../../../../docs/观众视角与制作避坑.md)作陌生观众审片：记录实际开头、观看推进、兑现和可能划走的区间；有动作/字幕齐不等于值得看。用户整条投诉保留原目标，动作子项改善不得缩小后标resolved。已确认内容价值/视觉体验不成立，必须在既有content/visual和finding中留issue/open；版本记录齐全不能抵消失败。`night-garden-1114/v0003`的旧放行为本项目明确反例。

使用 `status` 和该版 `receipt.json` 确认作品 ID、父版、活动候选、产物哈希与待完成状态。`current_role=candidate`尚不可交付；`reviewed_candidate/delivery_ready=true`仅表示同版记录满足现有交付检查，不表示真人/用户认可。新候选须先成功准备审查材料，再推进current和清理pending；准备失败保留父版、完整候选和pending，`review_preparation_pending`可在续做授权下复用候选收尾。打开确切版本核对全片开始、关键动作、结束和跨镜头衔接。记录范围、方法、可观察现象、期望与证据路径。视觉关注构图、遮挡、接触和字幕时序，声音关注说话清晰度、原声、音乐与音效相对强度。全片节奏和重点段落分别记录，格式、解码、实际播放、视觉、真实听审、内容核对、用户认可与平台反馈分别标记。无法观察的标 `unobserved`，程序核验仅绑定版本。

对有因果动作的镜头检查接触前后状态，例如 NFC 有可见的接触对象和结果。对故事事件检查角色目标和灯亮后的实际后果。套件镜头检查 story、kit、编译内容和同版回执。样段只证明对应区间，整片另查声音、过场和铺垫。问题用时间码或镜头 ID 绑定，优先做可解释的小改；同样改法无改善就回到原因和路线选择。

## 完整视听与人工验收

### 一次审查的三份主记录

沿原目录 `works/<id>/reviews/<version>/<receipt-sha>/` 留三份主记录，不另建审查状态：

| 主记录 | 现有文件与用途 |
|---|---|
| 审查包 | `frames.json` 是冻结索引，绑定需求、成片、回执、全片帧和诊断附件 |
| 交叉核对表 | `cross-check.md` 逐条核对外部结论，记录采信、丢弃或待核对及依据 |
| 同版结论 | `review-save` 生成的最新 `rNNNN.json`；旧 r 修订只增保留，不再另写一份放行报告 |

`draft.json` 是同版结论的工作稿；原尺寸帧、拼图、预览、外部模型原报告、逐秒图、音频片段、播放遥测和一次性诊断脚本均为附件。新增附件放本审查目录的 `attachments/`，从核对表或结论引用路径和 SHA256，保留原报告；不把每种附件扩成一份独立审查结论。不改写 `frames.json` 或其已冻结附件来容纳新观察。

新 `review-prepare` 自动生成待核对表；恢复同绑定包不覆盖已有表，旧包缺表时直接在原目录补表，不重渲染或重抽帧。表首绑定作品、版本、成片与回执 SHA256，并登记外部报告附件的 SHA256、实际输入范围、观察方法和局限。没有使用外部报告时说明原因与剩余待验，不能编造调用或自动发起付费审片。

每条外部结论单列：`ID｜报告原结论与时间码｜源码/成片帧/独立音轨证据及SHA256｜采信/丢弃/待核对及理由｜finding ID/复验范围`。按所称现象选证据：源码证明意图，成片证明实际可见结果，独立音轨用于核对实际演唱；不能相互代替。字幕争议先做不提供目标歌词的实际盲听，保留不同听辨和能力限制，不按模型猜词补字。同一报告逐条处理，助手观察单列，不给放行分数。

采信的问题转入 `draft.json` 的对应 `issue` 和 `open finding`；证据不足保持待核对及相关检查 `pending`，先补证据再决定是否改片。丢弃须给反证及理由。保存前把核对表和实际观察附件作为相关 `checks/findings` 的 `evidence` 绑定 SHA256，再走 `review-save → review-status`；之后改动已绑定表或附件会使结论失效。现有程序核对证据哈希与记录状态，**不自动解析核对表、穷尽模型结论或确认看听真实发生**。

制作完成后自动准备 `works/<id>/reviews/<version>/<receipt-sha>/`：全片2fps原尺寸帧、拼图、诊断预览、冻结需求与待审draft。既有片用 `--mode development review-prepare <id> --version <v>`；同绑定恢复复用，不覆盖。逐帧观察、全片连续播放、内容兑现与真实听审分别记录，`review-save`保存只增的r修订；`review-status`核同版源、完整覆盖、证据文件SHA和未解决问题。未观察保持pending，问题记issue/open；后续审查不得漏掉历史缺陷，解决须留证据。

`review-check`保留旧记录兼容，只证明归属和声明格式，不能授权交付。`export`、新离线发布包和导出workflow强制消费同版审查；缺审、过期、待审、有问题拒绝。原片诊断预览仍可查看；不能直接发附件冒充已验收。程序不能认证看听是否真实发生或自动判断审美，不把记录为pass等同于真人/用户认可。

2026-11-17 外部 AI 全片路径已用 v0010 实测，见[入口、实测与边界](../../../../docs/reviews/2026-11-17-连续画面审阅与返修闭环.md)。`aistudio_full_av_v1` 由原 `review-save` 消费，回执绑定原生全时段24fps视频、完整独立音轨、无画面／目标歌词的盲审、原始完成回复及逐条交叉核对；没有实际附件不能自填通过。它只校验绑定、覆盖和记录，不认证模型内部感知。`continuous_review.limitations` 原样保留报告局限；源片帧与模型采样精度、真人听审和用户认可分别记录。

`review-status` 的 `review_completion=complete` 说明在 `observation_scope` 明示范围内审完，`quality_status=issues` 表示审完仍有问题，继续阻止合格 export；`observation_limits` 必须同时保留。不能把质量失败重新叫待审，也不能为了结束任务关闭实际缺陷。旧冻结包和 r 修订不改写，新观察保存新 r；未核实分歧或证据缺口仍待审。上传仍须有效授权和实际支持的后台页面操作，不能启用收费或抢前台完成审查。

| 检查 | 应实际做什么 | 应留下什么 |
|---|---|---|
| 连续视觉／节奏 | 从头到尾正常速度观看；按语义段落对照原片；覆盖全片、所有转场、关键动作前／中／后 | 版本与视频哈希、方法、完整范围、问题时间码、实际观察；截图仅证明截图本身 |
| 字幕 | 手机尺度或等效预览核阅读时间、重叠、遮挡、出入场、唯一主阅读区 | 具体问题区间及修后同版观察；字数检查不能代替读得清 |
| 连续听审 | 实际听完整最终文件中的BGM／SFX，核情绪、峰值、音画同步、接缝、起止和结尾 | 实际可听方法、范围和听感；ASR、波形、响度、音轨存在都不等于听过 |
| 封面 | 打开最终导出封面，检查标题完整、主体、透视、持握／接触、裁切和手机重点 | 该封面路径／哈希、实际图像及结论，不能只验视频某个固定秒数 |
| 人工视觉 | 真实人员看完整片；重点回看上表视觉问题及参考差距 | 审片人、日期、版本／哈希、范围、结论、真实消息或审片记录 |
| 人工听觉 | 真实人员听完整最终音轨，可与视觉同次进行但分别给结论 | 听审人、日期、版本／哈希、范围、实际反馈证据 |

AI图像观察、工具播放、真人视觉、真人听觉、用户认可分别标记；同一人可以承担多项，但没有真实证据不能代签或补造。旧试制的用户否决保留；2026-11-14对两条运营包“还可以”、封面六七分的反馈也须保留，但不扩大为整片视觉、听觉或流量认可。没有可听／可看能力时保留`pending`，真实人员未审为待验；整片候选只能明确提供诊断预览，不能声称已通过交付验收或人审。用户反馈若明确涉及完整观看／声音，可按其实际范围记录，不能擅自扩大范围。

字幕、音乐、画面、剪辑或封面变化后，按变化使相应旧观察失效：时间线变动要重查同步及全片节奏，声音更换要重新听审，封面改变要重看最终封面。人审结论只属于其实际看过／听过的版本。

- 只改代码画面，补丁写 `base`、`shot` 和 `visual`。复用父版音频、SRT 和非目标镜头。新增场景资产先纳入作品；当前画面补丁可引用已登记素材。Workflow 与实际返修共用补丁后的完整 brief/输入校验，颜色等无效字段值或冻结输入哈希不符时停止，不修改父版或重写哈希凑通过。
- 原生剪辑使用 `native-edit-plan`，写 `base`、`timeline_sha256`、`operations` 和 `locked`。音轨锁 `audio`，录屏自带原音还需锁 `clips`；原生时间改变可能重映射字幕与音频。候选通过且获准后才执行 `revise-native`。
- 原生返修交接单也写 `locked`，将用户文字 `locks` 映射到同名轨道，检查补丁没有漏锁。核对返回的补丁哈希；交接不代替实际入口的再检查。导入树或冻结父版与工程包不符时，保留现场，从原包另建工程，不在父版上修文件凑校验。
- `status` 找到本地候选后确认继续、归档或回退。`abandon-candidate` 归档确切的未完成版本，保留现场；活动版另核同版质量后交付。来源或远端任务状态未知时先找原任务号和回执。
- 已经制作并审查的版本交付前检查 `review-status` 与交付回执，使用 `export --version` 将复制绑定同一版。新版本出现后旧审查继续归属旧版本。发布另行授权。
